SharedBrain documentation

SharedBrain is a local-first knowledge base with a multi-agent answer pipeline. Specialized agents share one persistent SQLite memory, answers cite the sections they came from, and questions the knowledge base can't support are declined.

It is a single Node.js process with no external services. The web UI, the HTTP API, a file-drop ingester and a CLI all run on top of the same database file.

  • Ask — ask questions and watch the agent pipeline run.
  • Knowledge — browse, write, and import documents.
  • Graph — explore how documents link together.
  • Console — review memories, build context packs, back up data.

Quick start

Requires Node.js 20 or newer. On macOS you can also use the desktop app, which bundles everything.

npm install
npm run serve
# → SharedBrain Web UI running at: http://localhost:3000

The first start creates data/shared_brain.db and seeds a sample knowledge base about a fictional API platform called NexusFlow, so there's something to ask about straight away. Try:

  • “What are the rate limiting tiers?”
  • “How do I roll back a SEV-1 incident?”
  • “What is the capital of France?” — this one is declined, because nothing in the knowledge base covers it.

No API key is needed. Without one, answers are extractive: the most relevant passages are quoted with citations. Add a model in configuration to get written answers.

macOS app

SharedBrain-1.0.0-arm64.dmg contains a native app that bundles its own Node.js runtime, so nothing else needs to be installed. It runs on Apple silicon Macs with macOS 13 or later.

  1. Open the DMG and drag SharedBrain into Applications.
  2. The app isn't notarized, so the first time, right-click it in Applications and choose Open, then confirm. If macOS still refuses, open System Settings → Privacy & Security and click Open Anyway.
  3. The app starts the server on a free local port and opens the UI in its own window.

If the app was copied over AirDrop or downloaded and won't open at all, clear the quarantine flag once:

xattr -dr com.apple.quarantine /Applications/SharedBrain.app

The active model is shown in the header of every page. If a model call fails, SharedBrain falls back to an extractive answer instead of erroring.

Adding knowledge

There are four ways in. All of them make content searchable immediately.

  • Write a document on the Knowledge page. Markdown is supported, and [[Note title]] links to other notes.
  • Import files with the upload button on the Knowledge page, or drag files anywhere onto it.
  • Drop files into the drop folder (data/incoming, or the app's folder on macOS). They're picked up within a few seconds and moved to processed.
  • Call the API: POST /api/ingest with a title and content.

Supported file types: .md .markdown .txt .json .csv .log .yaml .yml .ts .js .py .sql.

Imported and dropped files also go through distillation: lines that read like decisions (“we decided…”), constraints (“must not…”), conventions, and bug fixes become memories, each stored with the exact quote and byte offsets it came from.

How answers work

Every question runs through four stages. The Ask view streams each one with its measured duration.

AgentStageWhat it does
ResearcherRetrievalSplits every document into heading sections and ranks them, along with ingested chunks, using BM25. Titles and headings are weighted higher. Related memories are ranked the same way.
AnalystScope checkMeasures what share of the question's terms appear in the top passages. Below 50%, the question is declined.
WriterAnswerWith a model configured, writes an answer from the numbered passages only, citing them as [1], [2]. Without one, quotes the most relevant lines.
CriticGrounding checkReports the share of the answer's terms that appear in the sources, shown as “% grounded”.
Declining is deliberate. A question about something the knowledge base doesn't contain gets a short explanation and a list of topics that are covered, never an invented answer.

Memory model

A memory is a short statement with a kind (decision, constraint, convention, bug_fix, lesson, reference), a subject key, a status, and one or more evidence records quoting the source.

Statuses move only through one transition function, with optimistic version checks:

suggested → approved | archived
approved  → archived | superseded (requires an approved successor)

The engine enforces eight invariants, reported by GET /v1/health:

  1. No memory without evidence.
  2. Claims and evidence are stored separately.
  3. Model output is untrusted until verified against a verbatim quote.
  4. All status changes go through one transition function.
  5. Feedback adjusts ranking but never rewrites memories.
  6. Context packs are reproducible.
  7. Projects are isolated from each other.
  8. Extraction is idempotent.

Context packs

A context pack is a token-budgeted bundle of approved memories, with evidence, selected for a query and rendered as Markdown. Use it to give another LLM or agent the relevant team knowledge without dumping whole documents. Build one in Console → Context packs or via POST /v1/context-packs.

HTTP API

All endpoints accept and return JSON. /api/* powers the web UI. /v1/* is the memory-engine API, scoped to a project. Without an Authorization header it uses the built-in local development key, so it works out of the box on localhost.

Questions

POST/api/ask{ question } → { answer, citations, isRefusal, groundingScore, … }
POST/api/tasks{ task } → Server-Sent Events: agent_start, agent_complete, critic_complete, task_complete, done
GET/api/conversationsQuestion history. GET/DELETE /api/conversations/:id for one.

Knowledge

GET/api/documentsAll documents.
GET/api/documents/:idOne document with backlinks and outgoing links.
POST/api/documents{ id?, title, folder, content, tags, pinned } — create, or update when id is given.
DELETE/api/documents/:idDelete a document and its links.
POST/api/ingest{ title, content, folder? } — store, chunk, and distill memories.
GET/api/graphNodes and edges for the graph view.
POST/api/links{ sourceId, targetId, context } — link two documents.

System

GET/api/systemVersion, active model, storage paths.
GET/api/ingest/statsCounts of documents, chunks, memories, links.
GET/api/export/databaseDownload a consistent SQLite backup.

Memory engine (/v1)

GET/v1/memoriesFilter with status, kind, subjectKey.
POST/v1/memories/:id/transitions{ newStatus, expectedVersion }
POST/v1/memories/:id/feedbackRecord useful / outdated / worked / failed.
POST/v1/context-packs{ query, budget } → pack. GET /v1/context-packs/:id/markdown to render.
GET/v1/review-itemsOpen review items. POST …/:id/resolve with { action }.

GET/v1/healthTable counts and invariant status.

OpenAI-compatible proxy

POST /v1/chat/completions accepts a standard chat request. SharedBrain builds a context pack for the latest user message and injects it into the system prompt. With a model configured, the request is forwarded upstream. Without one, it answers from the knowledge base directly, with sources.

from openai import OpenAI
client = OpenAI(base_url="http://localhost:3000/v1", api_key="sb_live_demo_key_2026")
reply = client.chat.completions.create(
    model="sharedbrain-core",
    messages=[{"role": "user", "content": "How are webhooks signed?"}],
)

This works with tools that accept a custom OpenAI base URL, such as AnythingLLM, Open WebUI, or Continue.

Troubleshooting

The server crashes on start with a segmentation fault

The native SQLite module was built for a different Node.js version. Run npm rebuild better-sqlite3, or delete node_modules and run npm install again.

Port 3000 is already in use

The server automatically moves to the next free port and prints the URL. Set PORT to choose one.

A question I expected to work was declined

Fewer than half of its key terms appear in the knowledge base. Rephrase it with words the documents use, or add a document that covers the topic.

The macOS app says it's damaged or can't be opened

That's Gatekeeper reacting to an unsigned app copied from another Mac. Run xattr -dr com.apple.quarantine /Applications/SharedBrain.app once.
